# Проверенные операции SDK v21

Источник точных сигнатур: локальные `SDK/Include/KsTLB.pas` и `LDefin3D.pas` установленного КОМПАС v21. Не подменяй их документацией другой версии.

Официальные справочники помогают с терминологией, но следующие онлайн-страницы относятся к более новым версиям:
- [Сопоставление типов объектов API5 и API7](https://help.ascon.ru/KOMPAS_SDK/25/ru-RU/obj3dtype.html).
- [Параметры операции по сечениям](https://help.ascon.ru/KOMPAS/23/ru-RU/parametry_operaciy_po_secheniyam.html).
- [Оболочка: ksShellDefinition](https://help.ascon.ru/KOMPAS_SDK/23/ru-RU/ksshelldefinition.html).

## Условия воспроизведения

Python с pywin32 и установленным пакетом `kompas_local_mcp`, запущенный КОМПАС v21, доступ к его COM ROT. Используй тот же уровень доступа, что у приложения. Скрипт `scripts/probe_complex.py` создаёт собственные новые документы, сохраняет четыре M3D, проверяет native feature и повторное открытие. Запускай при свободном STA, отдельно от активных MCP-запросов:

```powershell
& <repo>\.venv\Scripts\python.exe <skill>\scripts\probe_complex.py --output <absolute-test-folder> --executable <absolute-KOMPAS.exe>
```

Это диагностический прямой SDK-клиент, а не опубликованный MCP-инструмент. Повторный запуск использует новые имена выходных файлов. Он не предназначен для редактирования готовой пользовательской модели.

Системы эскизов: XY=(u,v,h), нормаль +Z; XZ=(u,h,-v), нормаль +Y; YZ=(-h,-v,-u), нормаль -X. Смещение плоскости следует нормали. Методы адаптера создают скетч и возвращают session token; только внутри STA `_model_ref` даёт COM `ksEntity`.

## Loft — тело по сечениям

`NewEntity(30)` → `ksBaseLoftDefinition`; добавление — `ksEntityCollection(definition.Sketchs()).Add(sketchEntity)`, в пространственном порядке. В проверенной пробе:

- `SetLoftParam(False, False, True)`;
- три окружности XY: `(offset_z, center_x, center_y, radius)` = `(0,0,0,20)`, `(30,8,0,14)`, `(60,-4,0,10)`;
- одно тело, объём 40543.756173 мм³, высота 60 мм;
- native `Create`, rebuild, feature valid/error=0 и Save/Close/Open прошли.

Поверхность выходит до X=22.930321, хотя максимум сечений X=22. Не считай габариты loft простым объединением габаритов эскизов. Для полигонов сохраняй число и порядок соответствующих вершин. Направляющие, тонкий loft, boss/cut loft, произвольные плоскости и сложные переходы этим тестом не подтверждены. В SDK есть типы 31/32 и SetThinParam, но перед публикацией нужны отдельные пробы.

## Sweep — движение профиля по траектории

`NewEntity(45)` → `ksBaseEvolutionDefinition`; `SetSketch(profileEntity)`; `PathPartArray()` → `ksEntityCollection.Add(pathSketchEntity)`; в проверенной пробе `sketchShiftType=1`.

Профиль — окружность R4 на XZ, центр (0,0). Траектория — эскиз XY с `ksArcByAngle(25,0,25,180,90,-1,1)` внутри BeginEdit/EndEdit: четверть окружности R25 от (0,0) к (25,25), начальная касательная +Y. В Python этого SDK имена методов отличаются от Pascal: проверено `array()`, не `array_()`.

Одно тело, объём 1973.920880 мм³, совпадает с `π·4²·(π·25/2)`; габарит 29×29×8 мм. Native и reopen прошли. Это **сплошной стержень**, не полая труба. Кольцевой профиль, тонкий sweep, составной путь, spline и 3D-path отдельно не подтверждены. Для трубы нужны дополнительные пробы; радиус центральной линии должен превышать наружный радиус профиля, а сложный путь требует контроля самопересечений.

BeginEdit открывает native режим до обёртки COM: защищай саму обёртку try/finally. EndEdit должен выполняться и при ошибке записи.

## Fillet — скругление

`NewEntity(34)` → `ksFilletDefinition`; `radius=2`, `tangent=False`; `array()` → `ksEntityCollection`; Add каждого из 12 рёбер `part.EntityCollection(7)` коробки 30×20×40.

Все рёбра R2 прошли: объём 23701.687230 мм³ вместо 24000, внешний габарит сохранён; native, reopen, STL прошли. Этот рецепт выбора всех рёбер применим только к такой коробке. Для проектной детали выбирай рёбра по владельцу, типу, положению и смежным граням; индекс после перестроения нестабилен. Публичный `list_model_topology(kind="edge")` реализован и проверен на solid-топологии; ссылки истекают при rebuild. Большой радиус может разрушить тонкие участки.

## Shell — оболочка

`NewEntity(43)` (не 40) → `ksShellDefinition`; `thickness=2`, `thinType=False`; `FaceArray()` → ksEntityCollection, Add одной удаляемой грани коробки 30×20×40.

В тесте первая грань коллекции оказалась верхней Z=40. Получена **наружная** открытая оболочка: габариты min=(-2,-2,-2), max=(32,22,40), объём 10272 мм³. Native, reopen и STL прошли. Выбор `GetByIndex(0)` — только характеристика тестового блока, не способ выбора верхней грани в произвольной детали.

Без удаляемых граней `Create()` вернул True, но `objectError=54`: такую операцию считать неуспешной. Внутреннее направление `thinType=True`, переменная толщина и shell на loft не проверены; прежде чем проектировать канал, подтвердить их отдельным тестом. После shell измерять фактические габариты и проходы.

## Экспорт и интеграция в MCP

Текущий `export_model` сверяет размеры STL с native bounds с допуском 0.05 мм. На loft и sweep он отверг результат: `STL/model bounds mismatch`. Файлы не опубликованы; M3D корректны и повторно открываются. Причина расхождения здесь не установлена. Не ослабляй проверку вслепую и не обещай готовый STL: исследуй настройки тесселяции, координаты и допустимую погрешность. На fillet/shell STL прошёл.

При добавлении инструментов валидируй конечные числа, положительные радиусы/толщины, принадлежность ссылок документу, число/порядок сечений и доступные операции. При сбое удаляй созданную операцию, rebuild, проверяй восстановление; при неудаче rollback сообщай об оставшемся объекте. Не возвращай COM через MCP.

`model_state/rebuild_model` дополнены новыми типами и их native ошибками; при расширении продолжай проверять public schema, stdio-вызов, отрицательные случаи и сохранение/reopen. Сохранённая base-операция может иметь boss-тип: учитывать реальные определения, не фиксировать один тип навечно. Прямой SDK успех сам по себе не считается проверкой MCP-команды.
