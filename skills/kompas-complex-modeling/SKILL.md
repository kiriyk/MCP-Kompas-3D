# Сложные формы в КОМПАС-3D v21

Используй вместе с установленным `kompas-mcp-workflow`: он описывает подключение, единицы, документы и существующие MCP-команды. Этот skill добавляет выбор операций, проверенные SDK-рецепты и проектирование по картинке.

## Возможности и границы

Сначала проверь текущий `tools/list`. В MCP v0.8 опубликованы и проверены через stdio: `sketch_arc`, `loft` (base/boss/cut), `sweep` (base), `shell`, `fillet`, `list_model_topology`, `set_model_display`, `export_model_png`. Параметры бери из схемы инструмента. Loft требует минимум два упорядоченных замкнутых сечения; sweep — профиль, нормальный касательной начала траектории. Shell использует `inward`; ссылки граней/рёбер действуют только до rebuild.

Топологию перечисляй через тела: BodyCollection → ksFaceCollection (определения граней) → GetEntity(); EdgeCollection возвращает ksEdgeCollection (определения рёбер) → GetEntity(). Part.EntityCollection включает вспомогательные плоскости и эскизы. Для прямых рёбер габариты вычисляй по вершинам; GetVertex возвращает определение вершины, а не сущность.

`set_model_display(transparency_percent=0)` делает деталь непрозрачной и включает затенение. В API7 Transparency — непрозрачность: 1 означает непрозрачное тело, 0 невидимое. Только для намеренно прозрачного окна используй другое значение. COLORREF имеет порядок BBGGRR. PNG экспортируй с raster colorType=3.

При доработке MCP читай [SDK-рецепты](references/sdk-operations.md), воспроизводи отдельную пробу, затем добавляй валидируемый Adapter и проверяй вызов через stdio. Прямая COM-проба уместна в разрешённой разработке MCP; обычный пользовательский запрос на модель сам по себе не требует менять сервер или его регистрацию. Сохраняй выбранную пользователем среду и точность формы.

Если нужной команды нет, выбери доступный путь в рамках запроса: доработка MCP при уже разрешённой разработке, прямой SDK при разрешённой автоматизации, либо интерфейс КОМПАС при доступном управлении приложением. При действительно отсутствующем способе укажи конкретный недостающий шаг и продолжай независимые части модели; не объявляй проект выполненным после одного плана и не запрашивай повторно уже данное разрешение.

## Выбор формы

| Геометрия | Операция | Что сначала проверить |
|---|---|---|
| Изгибающийся корпус с изменением ширины | Loft по сечениям | Порядок, соответствие контуров, выход поверхности за сечения |
| Гнутая труба постоянного сечения | Sweep по траектории | Профиль у начала, нормаль к касательной, радиус изгиба |
| Стенка постоянной толщины | Shell | Направление толщины, удаляемые грани, локальные радиусы |
| Мягкие края и сопряжения | Fillet | Семантический выбор рёбер, допустимый радиус |
| Скульптурное лицо | Отдельная декоративная деталь | Нативный упрощённый рельеф либо отдельно проверенный импорт |

Не заменяй гладкие трубы набором прямых сегментов, а переменное сечение — обычным выдавливанием без согласованного изменения формы. Не обещай точную скульптуру через ещё не проверенный импорт.

## От референса к модели

Осмотри саму картинку. Раздели функциональный канал, несущий корпус, декоративные накладки и цветные детали. Размеры, скрытые поверхности и соединения на одной перспективной картинке неизвестны: задай параметры явно и отмечай предположения.

Проверяй сходство по силуэту, пропорциям, размещению крупных узлов и цветам на сопоставимом ракурсе. Для существенного упрощения лиц или иных заметных деталей предложи конкретный образец для оценки; не считай такое изменение автоматически приемлемым.

Сначала обеспечь непрерывный путь кубика и доступ для сборки. Затем добавляй внешний силуэт, окно, трубы, скругления и декор. Разделяй цвета на отдельные сохраняемые детали; COLORREF имеет порядок `0x00BBGGRR`, STL не хранит цвет.

Для похожей башни читай [разбор концепта dice tower](references/dice-tower.md). Это пример инженерной декомпозиции, не универсальные размеры.

## Проверка

`Create()` недостаточно: rebuild → `ksFeature.IsValid()` и `objectError == 0` → количество тел, объём и реальные габариты → Save/Close/Open собственных тестовых деталей → повторная проверка. `model_state` перечисляет также loft, sweep, shell и fillet; проверяй ошибки всех формообразующих операций.

Проверь форму на видах и разрезах, толщину и проходы — по геометрии. PNG/PDF и отсутствие ошибок COM не доказывают движение кубика. Для чертежей используй реальные ассоциативные виды, размеры и контроль перекрытий на листе.

В MCP v0.8 опубликованы нативные проверки пересечений сборки и расстояний между выбранными гранями/рёбрами. Их результаты не доказывают минимальную толщину всего тела или движение кубика. Читай [проверку v0.8](references/inspection-v08.md); называй проверенные пары, пороги и фактическое покрытие.

Вызовы COM выполняй последовательно в одном STA. После тайм-аута исход неизвестен: прочитай состояние перед повтором. Не закрывай чужие документы. Для проверочного скрипта и известных ограничений экспорта см. SDK-рецепты.

Новые проверки, цвет/камера и повторяемые сборки: [v0.8](references/inspection-v08.md). Перед выдачей модели сравни с референсом в сопоставимом ракурсе: силуэт, пропорции, узлы, цвета и лица. Приложи реальный PNG; явно назови существенные упрощения. Для башни проверь опоры скатов, монтаж окна/труб и доступ к внутренним узлам через сервисную крышку.
