# Локальная работа с КОМПАС-MCP

Проверено 10.10.2026: Windows, КОМПАС-3D v21, MCP 1.0.22. Проверь существование путей и доступность инструментов перед повторным использованием.

## Пути и запуск

```text
КОМПАС: D:\ASCON\KOMPAS-3D v21\Bin\KOMPAS.exe
Ярлык: C:\Users\Public\Desktop\КОМПАС-3D v21.lnk
MCP: C:\Users\user\Documents\Codex\kompas-mcp\v1.0.22\KOMPAS-3D-MCP-bin\kompas-mcp.exe
Журнал: C:\Users\user\Documents\Codex\kompas-mcp\v1.0.22\KOMPAS-3D-MCP-bin\logs\mcp-kompas-3d.log
Python: C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe
```

Приложение запускай явно в пределах задачи пользователя:

```powershell
Start-Process -FilePath 'D:\ASCON\KOMPAS-3D v21\Bin\KOMPAS.exe' -WindowStyle Normal
```

На компьютере также есть продукты ASCON в Program Files; наличие v23 Home не означает, что нужно запускать её. Если путь изменился, прочитай TargetPath установленного ярлыка.

В песочнице список процессов может содержать только её процессы, а CIM может быть недоступен. Для разрешённого взаимодействия с приложением используй штатное одобрение команд вне песочницы. Не меняй глобальные настройки и авторизацию как побочное действие.

## Проверка контекста

Последовательность чтения: `bridge_status` → `list_open_documents` → `get_active_document` → подробный `preflight_context`.

```json
{
  "name": "preflight_context",
  "arguments": {
    "target": "2d", "scope": "deep",
    "include_view_metadata": true,
    "response_profile": "debug", "compact": true
  }
}
```

Проверь имя/путь документа, API5/API7, номер активного вида, `scale`, `origin`, `api5_reference`. В разных процессах КОМПАСа могут быть разные документы. `count=0` относится к этому подключению.

`describe_tool` может показать схему инструмента, выполнение которого запрещено. `execute_python_script` в проверенной конфигурации вернул `tool_not_allowed`; не использовать альтернативный канал для обхода запрета.

## Локальный клиент при зависании

Используй абсолютный путь к `<skill-directory>/scripts/mcp_client.py`, вычисленный относительно этого skill. Клиент запускает тот же MCP EXE в его рабочей папке; новый процесс скрыт. Выполняет initialize, notifications/initialized и затем tools/call, проверяя id ответов. Протокол 2024-11-05 был принят этим сервером.

Без аргументов клиент читает только активный документ и снимок состояния; bridge_status и подробный preflight в эту проверку не входят. Для полной диагностики или построения агент заранее составляет JSON-массив действий и передаёт путь к нему:

```powershell
# Подставь разрешённые абсолютные пути к skill и подготовленному JSON.
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' `
  '<skill-directory>\scripts\mcp_client.py' '<workspace>\work\actions.json'
```

Пример структуры файла:

```json
[
  {"name":"set_active_view","arguments":{"view_number":2,"compact":true}},
  {"name":"create_rectangle","arguments":{"x":0,"y":0,"width":25000,"height":5850,"style":1,"compact":true}}
]
```

Пример предполагает, что нужный документ и вид уже проверены. Для новой задачи агент вычисляет её собственные координаты.

Клиент читает stdout/stderr параллельно, имеет ожидание ответа и в finally завершает только свой дочерний сервер. Не завершай все процессы КОМПАСа/MCP. Тайм-аут чтения и отмена клиентского ожидания не гарантируют отмену команды: выясни, что произошло до повтора.

Проверь все уровни ответа: JSON-RPC error, MCP isError, structuredContent, JSON в text. Клиент сам останавливается только по первым двум; `success=false` анализируй отдельно. Если `set_active_view` вернул false, проверь текущий вид; если save вернул false, не заявляй о сохранении.

Код клиента явно включает UTF-8 stdout: без этого cp1251 падал при печати `Ø` уже после создания текста. Файлы действий — UTF-8; передавай JSON с корректным экранированием. В генераторе используй `call(tool_name, **kwargs)`: аргумент `name` конфликтует с именем вида.

Клиент исключает base64 изображений из печатного журнала. Сохранённый PNG открывай отдельно. Для нового сбоя при необходимости сохраняй stderr в рабочую папку, не выводя секреты.

## Фактический масштаб вида

Для 1:50 коэффициент равен `0.02`. В MCP 1.0.22 `create_view` принимал этот аргумент, но фактически создавал вид 1:1. Если эта проблема воспроизвелась, исправь объект вида:

```json
{
  "name": "transform_object",
  "arguments": {
    "reference": 1073741876,
    "scale_x": 0.02, "scale_y": 0.02,
    "origin_x": 0, "origin_y": 0,
    "compact": true
  }
}
```

Число reference — пример: **замени его свежим api5_reference нужного вида**. Не передавай ссылку на прямоугольник вместо вида. Проверь после операции scale, origin и размеры в owner-координатах. В проверенном случае размеры остались 25000×5850, а отображение — 500×117 мм.

Не повторяй преобразование уже исправленного вида: оно применяется относительно текущего масштаба. При нужном масштабе ничего больше не масштабируй.

`origin_x/y` в этой обёртке влияли на перенос: 160/250 удвоили привязку вида; нулевые значения её сохранили. Проверяй результат, не предполагай стандартный смысл центра масштабирования.

В SDK имя свойства `ksViewParam.scale_`: [справка АСКОН](https://help.ascon.ru/KOMPAS_SDK/25/ru-RU/ksviewparam_scale_.html). Связь этого имени с ошибкой обёртки не доказана.

## Подписи, оформление и сохранение

Активируй вид перед добавлением подписей. В проверенном плане тексты 2.5–3.5 мм были читаемы в виде 1:50; не умножай автоматически высоту аннотаций на знаменатель масштаба. Их размещение проверь по изображению.

Системный вид 0 используй для надписей в координатах листа, отдельный вид — для реальной геометрии. Для полноценных размеров используй размерные инструменты; линии с засечками и числовые тексты не являются ассоциативными размерами.

Стандартное создание документа дало А4 вертикальный. Настройку А1 не удалось выполнить доступными разрешёнными инструментами. Проверяй реальные возможности текущего сервера; если пользователь берёт оформление листа на себя, выполни геометрию независимо от него.

После save проверь success, обновление файла и путь активного документа. Существование прежнего файла само по себе не доказывает сохранение последних изменений; если есть сомнения, проверь время изменения и содержимое при безопасном повторном открытии, предварительно сохранив работу. В сессии перезапись прежнего файла не удалась, отдельное имя с путём через str(Path(...)) сохранилось. Причина не доказана: не объявляй проблему слэшей или блокировки файла установленным фактом. Не теряй результат: при необходимости сохрани отдельный вариант и явно назови его пользователю.

Предпочитай activate_document с open_if_missing=true для известного открытого файла. После повторного открытия обновляй ссылки.

У screenshot_document читай capture_mode: viewport может показывать только окно, 2d_graphic_raster — чертёж. Проверь изображение, а не только существование PNG.
