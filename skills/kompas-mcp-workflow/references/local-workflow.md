# Локальный запуск и одна сессия

Основной проект: `C:\Users\user\DevProjects\MCP-Kompas-3D`; Python: `.venv\Scripts\python.exe`; сервер: `-m kompas_local_mcp.server`. Это stdio, не HTTP. Не регистрируй сервер глобально и не меняй настройки подключений без запроса. При переносе проекта проверь пути, editable-install и фактический импорт модуля.

## Запуск

Проверь процесс и путь EXE средствами PowerShell. Если КОМПАС не работает, агент запускает его сам:

```powershell
Start-Process -FilePath 'D:\ASCON\KOMPAS-3D v21\Bin\KOMPAS.exe' -WindowStyle Hidden
$env:KOMPAS_EXECUTABLE='D:\ASCON\KOMPAS-3D v21\Bin\KOMPAS.exe'
$env:KOMPAS_MCP_CACHE='C:\Users\user\DevProjects\MCP-Kompas-3D\.kompas-cache'
$env:PYTHONIOENCODING='utf-8'
```

Дай приложению завершить запуск. Не запускай второй экземпляр вслепую. `connect(launch=True, executable=...)` — запасной путь; диалог лицензии/старта может блокировать COM. Наш сервер не наследует инструменты старого EXE MCP.

## Клиент без регистрации подключения

Используй абсолютный путь к `scripts/mcp_client.py` этого скилла. Клиент переходит на Python проекта и использует проверенный `examples/client.py`. Он запускает один процесс сервера на весь пакет. Без `--actions` делает только `tools/list`; `--schemas` выводит полные актуальные схемы. Стандартный вывод сервера зарезервирован для JSON-RPC; диагностика — stderr.

```powershell
& 'C:\Users\user\DevProjects\MCP-Kompas-3D\.venv\Scripts\python.exe' '<skill>\scripts\mcp_client.py' --schemas
& 'C:\Users\user\DevProjects\MCP-Kompas-3D\.venv\Scripts\python.exe' '<skill>\scripts\mcp_client.py' --actions '<absolute>\actions.json'
```

Пакет — UTF-8 JSON-массив. `bind` сохраняет поле верхнего уровня ответа; строка `${doc}` заменяется значением переменной в последующих аргументах. Это не шаблонизация частей строк. Пример нового документа (выполняй только когда создание входит в задачу):

```json
[
  {"name":"connect","arguments":{}},
  {"name":"create_drawing","bind":{"doc":"document_id"}},
  {"name":"set_sheet","arguments":{"document_id":"${doc}","format":"A0","landscape":true}},
  {"name":"create_view","arguments":{"document_id":"${doc}","name":"План","scale":0.02,"x":50,"y":50}},
  {"name":"document_state","arguments":{"document_id":"${doc}"}}
]
```

Для существующего CDW замени create_drawing на `open_document` с абсолютным `path`. Открытый в UI файл сам по себе не зарегистрирован в сервере. open_document повторно использует только собственный реестр сервера; глобального поиска открытых документов нет. Если CDW уже открыт в UI, сначала установи, есть ли несохранённые пользовательские изменения. Documents.Open не доказан как безопасный способ получить именно этот изменённый документ: не переоткрывай его вслепую и не сохраняй поверх без понимания состояния. При неизвестном состоянии уточни у пользователя, сохранив независимую работу. Для неизвестного пути сначала выясни путь; не придумывай document_id. Для адаптивной работы держи `examples.client.Client` открытым в одном Python-скрипте; изучи его реализацию, вызывай `client.call`, обрабатывай фактические ответы и делай выбор объектов до мутации. Не считай bind полноценным языком выбора объектов.

Клиент проверяет названия всех инструментов и имена bind до первого действия, останавливается на ошибке и не повторяет изменения. Ожидание транспорта — 75 с, больше 60 с worker. При timed out/worker busy он удерживает сессию и каждые 5 с проверяет освобождение через read-only connect; после ответа завершает пакет с ошибкой. Это не проверка результата мутации: затем зарегистрируй документы заново и прочитай состояние. При отказе транспорта восстановление может оказаться невозможно; исход остаётся неизвестным. Каждый его запуск создаёт новую сессию: прежние document_id/reference не переносить. Числовой api_reference не использовать как токен. Повторный list_objects может выдавать новые токены того же объекта; удаление делает все его токены недействительными. После Close/Open также найди объекты заново.

## Зависание и неопределённый исход

STA worker сериализует COM; тайм-аут операции 60 с. Нельзя параллельно запускать прямой COM, второй клиент или повтор операции. Тайм-аут не отменяет выполняющийся COM; worker может оставаться занят, и новый запрос будет отклонён. Сохрани название/аргументы/последний подтверждённый результат, дождись завершения, затем прочитай состояние. Не повторяй изменение пока не выяснен исход. Не заканчивай клиент сразу после тайм-аута как способ отмены.

Проверь диалоги КОМПАС и живость процесса разрешёнными средствами; отсутствие активного документа, блокирующий диалог и недоступный COM — разные причины. Работай с файлами/логами, пока COM занят. Не убивай КОМПАС и не закрывай несохранённые чужие документы ради диагностики. Если прямой API необходим, сначала заверши сессию MCP и убедись, что worker не выполняет операцию. Новая сессия требует новой регистрации документов и ссылок.

При ошибке проверь stderr, установленное окружение, EXE v21, typelib/cache, путь CDW и права на каталог. Сначала устрани конкретную причину; не возвращайся автоматически к старому EXE-серверу.
