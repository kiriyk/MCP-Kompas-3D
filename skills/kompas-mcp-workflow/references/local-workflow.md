# Подключение к зарегистрированному серверу

Работай через инструменты kompas-local-mcp, зарегистрированные в текущем MCP-клиенте. В Codex рекомендуемое имя подключения — `kompas_3d`; имя префикса инструментов зависит от регистрации. Не используй старый EXE-сервер с похожим названием: проверяй доступный набор методов и параметры. Скилл не запускает собственный MCP-клиент.

## Настройка и пути

Сервер запускается установленным Python: `python -m kompas_local_mcp.server` либо установленной командой `kompas-local-mcp`. В конфигурации клиента указывается полный путь к Python нужного окружения. Корень репозитория, Python и установка КОМПАС определяются на каждой машине отдельно. Шаблон для Codex — `config/codex.example.toml` в репозитории; замени примерные пути локальными и не коммить заполненную конфигурацию.

Параметры среды сервера:

- `KOMPAS_EXECUTABLE`: полный путь к KOMPAS.exe v21. SDK по умолчанию определяется как соседний с Bin каталог SDK.
- `KOMPAS_SDK`: отдельный путь SDK, если структура установки отличается; нужен lib/kAPI5.tlb и lib/kAPI7.tlb. Без executable подключение к уже запущенному приложению возможно по SDK; запуск приложения требует executable.
- `KOMPAS_MCP_CACHE`: необязательный каталог generated COM wrappers. По умолчанию используется каталог во временной папке ОС, без привязки к репозиторию.
- `PYTHONIOENCODING=utf-8`: кодировка stdio. stdout зарезервирован для MCP JSON-RPC; диагностика — stderr.

Пример локальных параметров с условными путями (не готовая конфигурация конкретной машины):

```toml
[mcp_servers.kompas_3d]
command = "C:/path/to/MCP-Kompas-3D/.venv/Scripts/python.exe"
args = ["-m", "kompas_local_mcp.server"]
startup_timeout_sec = 60
tool_timeout_sec = 75

[mcp_servers.kompas_3d.env]
KOMPAS_EXECUTABLE = "C:/path/to/KOMPAS-3D v21/Bin/KOMPAS.exe"
PYTHONIOENCODING = "utf-8"
```

Если инструментов нет, проверь имя/включённость регистрации, существование Python и импорт установленного пакета, журнал старта MCP. После изменения конфигурации потребуется обновить подключение или перезапустить клиент. Не переходи автоматически к прямому API из-за отсутствия регистрации. Прямой SDK используется только при отдельной задаче разработки/диагностики, см. api-development.md.

## Запуск КОМПАС

Сначала проверь процесс и фактическую установку v21. Если приложение не работает, агент запускает его сам по найденному/настроенному пути; не проси пользователя запускать приложение, когда доступен разрешённый запуск. Если переменная настроена и доступна в оболочке:

```powershell
if (-not $env:KOMPAS_EXECUTABLE) { throw 'Set KOMPAS_EXECUTABLE to the installed KOMPAS.exe' }
Start-Process -FilePath $env:KOMPAS_EXECUTABLE -WindowStyle Hidden
```

Переменная в env MCP не обязательно доступна в оболочке; в таком случае прочитай локальные параметры подключения или найди установку, не угадывай путь. Дай приложению завершить запуск; не создавай второй экземпляр вслепую. `connect(launch=True, executable=...)` — запасной вариант, диалог старта может блокировать COM. Затем вызывай зарегистрированный `connect`.

## Регистрация документа и ссылки

`connect` не даёт document_id открытого окна. Вызови `create_drawing` для нового документа либо `open_document(path)` для существующего CDW и используй возвращённый document_id. Затем document_state, нужный вид, list_objects(owner). Общего get_active_document/list_open_documents нет: open_document повторно использует только собственный реестр сервера.

Если CDW уже открыт в UI, сначала установи, есть ли несохранённые пользовательские изменения. Documents.Open не доказан как безопасный способ получить именно этот изменённый документ: не переоткрывай его вслепую и не сохраняй поверх без понимания состояния. При неизвестном состоянии уточни у пользователя, сохранив независимую работу. Для неизвестного пути сначала выясни путь; не придумывай document_id.

document_id и reference действуют в одной сессии сервера и своём документе. Числовой api_reference — диагностика, не токен. Повторный list_objects может выдавать новые токены того же объекта; удаление делает все его токены недействительными. После перезапуска сервера или Close/Open зарегистрируй документ и найди объекты заново. Не инициируй перезапуск после каждого инструмента.

## Зависание и неопределённый исход

STA worker сериализует COM; тайм-аут операции 60 с. Настрой tool_timeout_sec клиента больше 60 с (например 75), чтобы получить ошибку worker прежде отмены транспорта. Это не продлевает сам COM-вызов.

Тайм-аут не отменяет выполняющийся COM; worker может оставаться занят. Сохрани название/аргументы и последний подтверждённый результат, останови изменения. Дождись завершения, затем проверяй освобождение read-only connect и фактическое состояние документа. Пока ответ содержит Worker busy, не выполняй мутации; увеличивай интервалы диагностики, не опрашивай непрерывно. Успешный connect доказывает доступность worker, а не результат предыдущего изменения. Не повторяй мутацию автоматически и не заканчивай сервер как способ отмены.

Не выполняй одновременно прямой COM, второй MCP-процесс и запросы зарегистрированному серверу. Проверь блокирующие диалоги и живость процесса разрешёнными средствами. Не убивай КОМПАС и не закрывай несохранённые чужие документы ради диагностики. После потери соединения исход остаётся неизвестным; повторное открытие требует учёта несохранённого состояния UI. При ошибке проверь stderr, Python, EXE v21, typelib/cache, путь CDW и права каталога; устрани конкретную причину.
